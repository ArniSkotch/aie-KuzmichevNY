## 1. Паспорт проекта

- **Название проекта:** `Создание сервиса фонемного выравнивания речи на базе Wav2Vec2`
- **Автор:** `Кузьмичев Никита Юрьевич`
- **Группа:** `БФБО-01-24`
- **Контакт:** `nkuzmichyov@yandex.ru`

- **Краткое описание (2-4 предложения):**  
> Проект решает задачу фонемного выравнивания (phoneme alignment) речи: по аудиозаписи модель определяет последовательность фонем и временные границы (начало/конец) каждой из них.
> В основе — предобученная модель `facebook/wav2vec2-lv-60-espeak-cv-ft` (CTC), применяемая к датасету TIMIT.
> Сырые CTC-границы дополнительно уточняются акустической постобработкой (`librosa.effects.split/trim`).
> Результат — REST API, который принимает аудиофайл и возвращает список фонем с таймингами, а также набор экспериментов и метрик, обосновывающих выбор финального варианта обработки.`

Пример:

> Проект посвящён построению сервиса рекомендаций фильмов на основе пользовательских оценок.  
> Используются открытые датасеты, простые модели коллаборативной фильтрации и baseline-модели на контентных признаках.  
> Результат – REST API, который по идентификатору пользователя возвращает список рекомендованных фильмов.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10` (уточните при необходимости).
- `espeak-ng` (нужен библиотеке `phonemizer` для разбора транскриптов в фонемы, когда у аннотации нет готовых сегментов с таймингами).
  На Linux/macOS обычно достаточно установить пакет из менеджера пакетов системы (`apt install espeak-ng` / `brew install espeak-ng`).
  На Windows нужно поставить eSpeak NG отдельно и указать путь к нему в `configs/config.yaml` → `env.espeak_path`.
- Аккаунт Kaggle с API-токеном — только если требуется самостоятельно скачать TIMIT (см. раздел 5).

### 3.2. Установка окружения

Примерный сценарий (можно адаптировать под ваш проект):

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
```

Эта команда создаст `configs/.env.example` (если его ещё нет) и добавит `configs/.env` в `.gitignore`, чтобы случайно не закоммитить секреты.

Скопируйте `configs/.env.example` в `configs/.env` и заполните `KAGGLE_USERNAME` / `KAGGLE_KEY`, если надо самостоятельно скачивать TIMIT (см. раздел 5).

## 4. Как запустить проект

Опишите, как именно воспроизвести основные сценарии использования проекта.

Примеры (заполните под свой случай):

### 4.1. Запуск обучения модели

Модель в проекте не обучается с нуля — используется предобученная `facebook/wav2vec2-lv-60-espeak-cv-ft` в режиме инференса.
«Обучающий» шаг для этого проекта — это подготовка датасета и прогон пайплайна по нему:

```bash
cd project
source .venv/bin/activate

# Скачивание + распаковка TIMIT и конвертация в единый формат audio/+annotations/
python -c "
from src.config import load_config, resolve_path
from src.data.download_timit import load_kaggle_credentials, download_and_extract_timit
from src.data.build_dataset import build_dataset

cfg = load_config()
load_kaggle_credentials()
extract_root = download_and_extract_timit(resolve_path(cfg['paths']['dataset_root']))
build_dataset(
    extract_root,
    resolve_path(cfg['paths']['audio_dir']),
    resolve_path(cfg['paths']['annotations_dir']),
    max_files=cfg['processing']['max_files'],
)
"

# Полный batch-прогон пайплайна: инференс + метрики по всем файлам
python -m src.run_pipeline
```

Все основные шаги (подготовка данных, EDA, демо-инференс на одном файле, полный batch-прогон, сравнение baseline/improved)
удобнее запускать из демонстрационного ноутбука `notebooks/exp04_voice_phoneme_pipeline.ipynb`.
Он последовательно вызывает тот же код из `src/`, ничего не дублируя.

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
source .venv/bin/activate
python -m src.service.api
```

Сервис поднимается на `http://0.0.0.0:8000` (хост/порт задаются в `configs/config.yaml` -> `service.host` / `service.port`).

Эндпоинты:

- `GET /health` — проверка, что сервис и модель загружены:

  ```bash
  curl http://localhost:8000/health
  ```

  ```json
  {"status": "ok", "model_loaded": true, "model_id": "facebook/wav2vec2-lv-60-espeak-cv-ft"}
  ```

- `POST /predict` — принимает аудиофайл (`.wav`/`.flac`/`.ogg`/`.mp3`), возвращает список фонем с таймингами:

  ```bash
  curl -X POST http://localhost:8000/predict \
       -F "file=@data/processed/input_audio/audio/TEST_DR1_FAKS0_SA1.wav"
  ```

  ```json
  {
    "source_file": "TEST_DR1_FAKS0_SA1.wav",
    "phoneme_count": 42,
    "segments": [
      {"phoneme": "h", "start_time": 0.0, "end_time": 0.08},
      {"phoneme": "ɛ", "start_time": 0.08, "end_time": 0.14}
    ]
  }
  ```

Внутри `/predict` использует ту же логику, что и улучшенный (`improved`) вариант из эксперимента сравнения:
сырые CTC-границы дополнительно уточняются акустической коррекцией (`correct_segment_boundaries`).

Swagger UI доступен по адресу `http://localhost:8000/docs`.

Сервис также можно поднять прямо из ноутбука (раздел 6), не блокируя остальные ячейки:

```python
from src.service.api import run_in_background
run_in_background()
```

> Docker-образ для проекта не подготовлен — это явное ограничение текущей версии (см. раздел 8).
> Сервис запускается напрямую через `python -m src.service.api` в виртуальном окружении, как описано выше.

## 5. Данные

Кратко опишите используемые данные:

> **Источник:** открытый датасет [TIMIT](https://www.kaggle.com/datasets/mfekadu/darpa-timit-acousticphonetic-continuous-speech)
  (DARPA TIMIT Acoustic-Phonetic Continuous Speech Corpus), зеркало на Kaggle.
  Содержит записи носителей 8 диалектов американского английского с эталонной фонемной разметкой (`.PHN`) и транскриптами (`.TXT`).
> **Где лежат файлы:**
  - `data/raw/timit/` — скачанный и распакованный архив TIMIT (не коммитится).
  - `data/processed/input_audio/audio/*.wav` и
  - `data/processed/input_audio/annotations/*.json` — унифицированный формат,
    полученный из TIMIT функцией `build_dataset()` (`src/data/build_dataset.py`):
    каждый `.json` содержит `transcript`, `segments` (список фонем со `start_time`/ `end_time` в секундах), `dialect`, `speaker_id`, `split`.
  - `data/processed/output_phonemes/` — результаты инференса (`metadata.json` на файл), сводные метрики (`metrics_summary.json`, `metrics_comparison.csv`) и
    результаты эксперимента сравнения (`model_comparison.csv/json`, `model_comparison_plot.png`, `boundary_accuracy_by_dialect.png`).
> **Объём:** для воспроизводимого запуска используется случайная подвыборка TIMIT (`processing.max_files` в `config.yaml`, в EDA — до 300 файлов,
  в эксперименте сравнения baseline/improved обработано 150 файлов), а не весь корпус — это сделано для скорости демонстрации, см. ограничения в разделе 8.
> **Как скачать самостоятельно:** заполнить `configs/.env` (см. раздел 3.2) и вызвать `download_and_extract_timit()` из `src/data/download_timit.py` (пример — в разделе 4.1).

Пример:

> Для обучения используется открытый датасет MovieLens (вариант small).
> В репозитории лежит только небольшая подвыборка в `data/sample_ratings.csv`.
> Полную версию датасета при необходимости можно скачать по инструкции из `data/README.md`.

## 8. Ограничения и дальнейшая работа

Кратко опишите:

> Текущие ограничения проекта:
>
> - **Нет Docker-образа.** Сервис запускается только через виртуальное окружение Python; единый `Dockerfile` не подготовлен.
> - **Используется не весь TIMIT.** Эксперименты проводились на случайной подвыборке (до 300 файлов в EDA, 150 файлов в сравнении baseline/improved),
>   а не на всём корпусе — результаты могут не полностью обобщаться на весь датасет.
> - **Модель не дообучалась на TIMIT.** Используется готовый чек-пойнт `facebook/wav2vec2-lv-60-espeak-cv-ft` "из коробки";
>   разница в наборах фонемных символов между espeak-фонемизацией модели и нотацией TIMIT — одна из вероятных причин относительно высокого PER (см. `report.md`, раздел 5).
> - **Эвристическая коррекция границ.** Уточнение границ через `librosa.effects.split/trim` (порог тишины `top_db`) — простой акустический эвристический метод;
>   он улучшает IoU и попадание в допуск 50 мс, но слегка ухудшает попадание в самый строгий допуск 20 мс.
> - **Сервис обрабатывает по одному файлу за запрос**, без батчинга, авторизации и хранения истории запросов.

> Что можно сделать дальше, если будет больше времени:
>
> - собрать `Dockerfile` и `docker-compose` для воспроизводимого развёртывания сервиса;
> - прогнать пайплайн и сравнение baseline/improved на полном датасете TIMIT, а не на подвыборке;
> - заменить эвристическую коррекцию границ на принудительное (forced) выравнивание через Viterbi/CTC-forced-alignment с учётом длительностей фонем;
> - добавить батч-обработку и простую авторизацию в `/predict`;
> - попробовать дообучить модель на TIMIT или использовать модель с фонемным словарём, более точно соответствующим разметке TIMIT.

Пример:

> В текущей версии в сервисе реализован только один метод рекомендации и нет авторизации.
> В дальнейшем можно добавить:
>
> - несколько алгоритмов с выбором через конфиг;
> - хранение истории запросов пользователей;
> - базовую авторизацию и логирование.
